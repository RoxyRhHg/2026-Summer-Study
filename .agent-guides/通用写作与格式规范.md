# 通用写作与格式规范

> [!important] 适用范围
> 本文件用于知识点型、讲解型、思维导图、碎片问答等学习笔记的通用表达、Markdown、公式、YAML 与双链规范。任务路由、资料优先级、长篇触发和子 Agent 门禁由根目录 `AGENTS.md` 决定；冲突时以根目录规则为准。

## 1. 内容表达

### 问题意识

知识点开始可以简短说明：

- 研究什么；
- 为什么出现。

但不要把知识点型笔记扩成整章讲解。

### 公式后要有人话解释

根据必要性说明：

- 变量是什么；
- 条件是什么；
- 结论意味着什么。

### 易混变量角色必须明确

尤其在统计估计、优化、逆问题中，明确：

- 什么是随机变量；
- 什么是已观测数据；
- 什么是优化变量；
- 什么被固定；
- 什么被估计。

### 类似模型必须比较

重点比较：

- 概率假设；
- 损失函数；
- 约束；
- 凸性；
- 使用场景。

### 不使用空洞跳步

避免用“显然”“容易得到”“可知”跳过决定理解的步骤。

如果某一步决定后续理解，应写出关键原因。

## 2. 术语格式

专属名词、定义名、短标签优先使用反引号，例如：

```markdown
- `最大似然估计`：选择最能解释已观测数据的参数。
```

不要默认使用粗体术语，也不要依赖中文引号强调术语。

## 3. 标题与列表

- 使用标题建立真正的知识层级；
- 子标题下面默认使用无序列表；
- 不用有序列表机械堆内容；
- 讲解版可以使用自然段；
- 思维导图以列表为主；
- 标题不要为了“显得详细”而不断细分。

## 4. 公式规范

### 行内公式

短公式优先 `$...$`。

例如：

```markdown
- `适用对象`：$y_i\in\{0,1\}$。
```

### 行间公式

较长或重要结构使用 `$$...$$`，并尽量保证两个 `$$` 与公式内容处于同一个物理行，例如：

```markdown
$$\ell(x)=\log p_x(y).$$
```

默认不要写成：

```text
$$
formula
$$
```

### 思维导图特殊规则

思维导图中行内公式优先；只有确有排版或结构需要时才使用行间公式。

### 禁止 boxed

不使用 `\boxed{}`。

重要性通过标题、文字和结构体现。

### 条件不能为排版省略

不能为了简短删除：

- 定义域；
- 正定条件；
- 非负条件；
- 参数约束；
- 适用前提。

## 5. Markdown 表格

- 适合比较时使用表格；
- 各行列数必须一致；
- 表格公式使用行内公式；
- 不在单元格塞长篇推导。

LaTeX 中不要使用裸 `|` 导致 Markdown 拆列。

优先：

- 绝对值：`\lvert r\rvert`；
- 范数：`\lVert x\rVert`；
- 条件：`\mid`。

Wikilink 别名中的竖线需要正确转义。

## 6. YAML Frontmatter

每篇学习笔记必须有 YAML。

最低字段示例：

```yaml
---
tags:
  - 暑假学习
  - 学习路径
  - 凸优化
created: 2026-08-29
updated: 2026-08-30
---
```

### tags

使用块列表：

```yaml
tags:
  - 凸优化
  - 统计估计
```

不要写成：

```yaml
tags: [凸优化, 统计估计]
```

### created

- 记录首次创建日期；
- 后续修改不能重置。

### updated

正文、公式、结构、双链或元数据发生实质修改时更新。

### 保留旧字段

旧文件已有 `type`、`title`、`aliases` 等有效字段时应保留，不要为了统一删除。

## 7. 双链

- 双链放在真正相关位置；
- 不要只在文末堆“关联”；
- 知识点型、讲解版、思维导图、碎片问答之间应形成自然网络；
- 长篇任务中的跨章节双链还需遵循 `长篇学习工作流.md` 的延迟审查原则。

## 8. 通用完成检查

### 格式

- YAML 是否完整；
- `created` 是否被误改；
- `updated` 是否更新；
- 是否有 `\boxed`；
- 行间公式是否符合单行规范；
- 表格列数是否一致；
- 表格中是否存在会误拆列的裸竖线；
- 是否错误使用粗体术语；
- 子标题下是否机械使用有序列表。

### 内容

- 是否出现不必要的重复；
- 是否为了压缩而删掉成立条件；
- 公式是否缺少必要解释；
- 符号角色是否清楚；
- 双链是否放在真正相关的位置。
