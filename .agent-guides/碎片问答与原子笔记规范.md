# 碎片问答与原子笔记规范

> [!important] 适用范围
> 本文件仅用于学习过程中临时出现的具体卡点、追问、辨析和局部推导，并将高质量问答沉淀为可独立复习的原子笔记。不用于整章讲解版、知识点型笔记或思维导图。是否进入本模式由根目录 `AGENTS.md` 判定。

## 1. 一篇只解决一个问题

标题直接写问题，例如：

- `似然函数中什么是变量，什么是已观测量`；
- `Logistic 损失为什么是凸函数`；
- `Bernoulli 负对数似然为什么等于交叉熵`；
- `为什么在线性化模型中加入二次惩罚`；
- `为什么不用更高次惩罚代替二次惩罚`。

如果回答过程中自然冒出另一个可独立成立的问题，应优先拆成新的原子笔记，而不是无限扩张当前笔记。

## 2. 默认理解路径

不要机械套固定标题，但应尽量遵循：

`先知道为什么问 → 再知道它在干什么 → 再看公式为什么成立 → 最后形成可复述的结论`

可按需要包含：

- 最小必要上下文；
- 明确问题；
- 问题意识；
- 直觉解释；
- 关键推导；
- 为什么不是别的做法；
- 最终结论；
- 必要条件 / 边界；
- 与当前问题高度相关的常见误区。

## 3. 优先处理“为什么”，再处理“怎么算”

碎片问答常见卡点是：

- 为什么会想到这个构造；
- 为什么偏偏选择这种形式；
- 这个系数从哪里来；
- 为什么不用看起来更直接的替代方案；
- 这个公式和前面知识有什么关系。

因此不要一上来只做公式推导。

例如解释二次惩罚时，不能只写：

$$\nabla f(y)+L(x-y)=0\Rightarrow x=y-\frac1L\nabla f(y).$$

还应先解释：

- 单独线性化为什么会无界下降；
- 为什么需要限制离当前点的距离；
- 为什么二次是最低阶且与 Taylor 误差匹配的选择；
- 为什么 $L$ 与 Lipschitz 梯度 / 曲率上界有关。

## 4. 推荐解释顺序

`一句直觉 → 一个最简单例子 → 一般公式 → 更深的理论来源`

例如：

- 先说“梯度告诉你往哪走，二次项告诉你别走过头”；
- 再用一维 $-ct+\frac L2t^2$ 解释为什么存在有限最小值；
- 再推到向量形式；
- 最后连接 Descent Lemma、Hessian 上界或 Lipschitz 梯度。

这种顺序通常比“定义 → 定理 → 证明”更适合真实学习卡点。

## 5. 推导逐步，但只展开决定理解的步骤

遇到关键公式时，不要使用“显然”“容易得到”“直接可知”跳过卡点。

判断标准：

> 省略这一步后，读者是否仍能解释“为什么从上一式能到下一式”？

如果不能，就应写出来。

同时不要把所有初等代数都展开到失去主线。

## 6. 主动回答“为什么不是另一个方案”

当用户卡点来自“为什么偏偏这样”，主动比较最自然的替代方案。

典型问题：

- 为什么是平方惩罚，不是一次、三次、四次；
- 为什么是最大化凹函数 / 最小化凸函数；
- 为什么 Logistic 对 log-odds 线性，而不是概率直接线性；
- 为什么同样是 $L_1$，作用在残差和参数上含义不同。

比较时说明真正判据，不要只说“因为更常用”。

## 7. 用最小真实例子落地抽象符号

当抽象符号难以形成直觉时，优先构造最小、可计算的场景，例如：

- 电子秤重复测量 → Gaussian 噪声 → 最小二乘；
- 欧姆定律 $U_i=I_iR+v_i$ → 线性观测；
- 疾病二分类 → Bernoulli + Logistic；
- 图像去模糊 → 数据保真项 + 先验正则项。

例子的作用是解释符号角色和因果关系，不要加入大量无关背景。

## 8. 符号角色必须明确

遇到统计、优化、逆问题时，应区分：

- 已知量；
- 观测量；
- 优化变量 / 待估参数；
- 随机变量；
- 残差 / 噪声；
- 当前迭代点；
- 局部模型中的候选点。

尤其当 $x,y,a_i,u_i,p_i,z_i$ 等连续出现时，不要默认读者能一直记住角色。

## 9. 一次回答尽量形成一条连续主线

避免大量彼此平行的小标题和重复总结。

一篇碎片问答应能压缩成一条因果链，例如：

`线性化无界 → 需要稳定项 → 二次项压住线性下降 → Lipschitz 梯度给出二次误差上界 → 最小化后得到步长 $1/L$`

或：

`Bernoulli 模型 → 似然 → 对数似然 → 负号 → 交叉熵`

如果读完后不能用一条链复述，说明内容可能仍太散。

## 10. 结尾只保留真正值得记住的结论

结尾可保留极短 `核心记忆`，通常只需要：

- 一句直觉；
- 一条关键公式；
- 一条与前后知识的连接。

避免正文、节末、最短记忆链、最后总结反复重复同一内容。

## 11. 原子笔记不是聊天记录搬运

落盘时应重新组织：

- 去掉寒暄和重复承接；
- 合并重复解释；
- 保留用户真正卡住的“为什么”；
- 保留关键推导和反例；
- 添加必要的 `[[双链]]`；
- 按 Obsidian Markdown 规范调整公式与术语格式。

目标：

`聊天时足够掰碎，落盘后足够清晰。`

## 12. 不复制整节笔记

碎片问答不是把知识点型笔记再抄一遍。

如果为了回答一个问题不得不覆盖整章多个知识点，应考虑：

- 核心卡点留在当前原子笔记；
- 其余内容通过 `[[双链]]` 连接到知识点型或讲解版；
- 或拆成多个独立原子笔记。

## 13. 双链

双链应放在知识关系真正发生的位置，例如：

- 二次惩罚 → `[[Lipschitz 条件]]`；
- 局部二次模型 → `[[梯度下降]]`；
- prox → `[[Proximal Gradient]]`；
- 近端梯度加速 → `[[0 FISTA（讲解版）]]`。

不要只在文末集中列一个问答清单。

双链的目的不是增加数量，而是把“这个卡点属于哪条知识链”固定下来。

## 14. 完成前自检

- 是否真的只解决一个核心问题；
- 是否先处理“为什么”，而非只给公式；
- 是否把用户真正卡住的数学步骤拆开；
- 是否主动比较自然替代方案；
- 是否使用最小必要例子；
- 符号角色是否明确；
- 是否能用一条因果链复述；
- 是否避免聊天记录式搬运和重复总结。
