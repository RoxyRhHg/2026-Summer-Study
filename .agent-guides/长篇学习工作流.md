# 长篇学习工作流

> [!important] 权限与触发说明
> 本文件只负责“长篇资料已经由根目录 `AGENTS.md` 判定触发之后，具体如何执行”。是否触发、是否必须创建子 Agent、失败时能否继续，均由根目录 `AGENTS.md` 决定；若与根规则冲突，以根规则为准。

## 1. 核心原则

`先建立全书地图，但不提前概括全书 → 每次只聚焦一个章节深读 → 所有章节分别完成后，再统一研究跨章联系与双链`

第一次学习主要解决：

`每一章到底讲了什么`

第二次全书综合才解决：

`这些章节为什么会组成一本书 / 一门课，以及它们之间怎样连接`

## 2. 第一阶段只扫描全书结构

开始处理整本教材、较长讲义或完整课程时，先读取：

- 目录；
- 前言 / syllabus / 课程大纲；
- 章节标题；
- 小节标题；
- 教材与讲义之间的大致章节对应关系。

这一阶段只确定：

- 全书有哪些部分；
- 有哪些章节；
- 每章大致边界；
- 哪些讲义 / PPT 对应哪些章节；
- 后续应按什么顺序逐章处理。

不得因为已经看过目录，就直接：

- 一口气概括所有章节内容；
- 提前总结整本书的核心思想；
- 预先替每章规定“真正主线”；
- 根据目录标题脑补章节内容。

原则：

`第一次全书阅读主要建索引，不提前建立最终结论。`

## 3. 章节研究采用内容上下文隔离

研究某一章时，知识内容上下文原则上只围绕当前章节展开。

当前章节 Agent 主要读取：

- 当前章节教材 Markdown / 原文；
- 当前章节对应讲义 / PPT Markdown；
- 当前章节必要附件；
- 根目录 `AGENTS.md`；
- 本文件；
- 当前任务产物对应的写作规范；
- 全书目录中用于定位当前章的最小结构信息。

默认不要同时把以下内容大规模带入当前章上下文：

- 其他章节完整正文；
- 其他章节完整笔记；
- 后续章节结论；
- 之前 Agent 对整本书的主观总括。

目的不是切断知识联系，而是避免：

- 当前章节细节被整书内容稀释；
- 尚未细读就被已有概括框住；
- 因提前知道后文而反向改写当前章的原始展开；
- 无法判断一个知识点在当前章究竟讲到了什么程度。

## 4. 允许最小必要回查

章节隔离不等于禁止查阅前置知识。

如果当前原文明确依赖其他章节中的：

- 定义；
- 定理；
- 公式；
- 符号约定；

且不回查就无法准确理解当前内容，可以定点回查必要部分。

例如当前章使用前文的 `Lipschitz gradient`，可以只回查该定义及理解当前推导所需的最小内容，而不是重新把前一整章读入当前上下文。

原则：

`需要什么，就回查什么；不要因为存在跨章引用，就把其他章节整体带入。`

## 5. 总控 Agent、章节 Agent 与全书综合 Agent

### 总控 Agent

负责：

- 读取根目录 `AGENTS.md`；
- 扫描全书目录与资料结构；
- 确认章节边界；
- 建立章节任务清单；
- 安排章节处理顺序；
- 记录章节完成状态；
- 保存待验证的跨章关系候选；
- 验收章节 Agent 的交付。

在所有章节深读完成前，总控 Agent 原则上不负责：

- 提前写最终全书总结；
- 给所有章节预设统一解释框架；
- 仅根据目录替各章定义核心思想；
- 提前构造完整跨章知识网络；
- 代替章节 Agent 深写正文。

即：

`总控 Agent 先负责调度，不抢章节 Agent 的内容研究工作。`

### 章节 Agent

章节 Agent 使用相对独立的章节上下文，负责当前章闭环：

`原文深读 → 章节结构确认 → 知识点型笔记 → 整章讲解版 → 思维导图 → 必要碎片问答 / 卡点记录`

章节 Agent 应优先保证：

- 当前章事实完整；
- 当前章内部逻辑清楚；
- 当前章教材与讲义对应准确；
- 当前章四类笔记各司其职。

章节 Agent 不应顺手承担整本书的知识网络设计。

### 全书综合 Agent

只有在所有章节都已经分别完成并验收之后，再进入全书综合阶段。

全书综合 Agent 优先读取：

- 全书目录；
- 各章思维导图 / 高密度章节摘要；
- 各章关键结构；
- 各章节留下的跨章候选关系。

先基于压缩后的章节结果建立全书关系，再对不确定关系定点回查原教材。

不建议一开始重新把整本原教材全部塞进一个超大上下文后再总结。

## 6. 默认按依赖顺序推进

`上下文隔离`不等于`所有章节同时并行`。

如果教材存在明显前后依赖，默认按照教材顺序执行：

`Ch1 Agent 完成并验收 → Ch2 Agent → Ch3 Agent → ...`

只有在章节明显彼此独立时，才适合并行，例如：

- 相互独立的应用专题；
- 附录型专题；
- 无前置依赖的案例章节。

原则：

`章节内容要隔离，任务调度默认仍按依赖顺序进行。`

## 7. 每章先纵向读透，再延迟处理跨章联系

当前章节尚未完成时，优先解决：

- 本章研究什么；
- 为什么这样展开；
- 定义、定理、公式和模型是什么；
- 本章内部知识如何连接。

对明显的跨章联系，可以先记录为：

- `跨章候选关系`；
- `待全书串联`；
- `待双链审查`。

例如：

- `proximal gradient ← 依赖 Lipschitz gradient`；
- `MAP ↔ 正则化`；
- `KKT → 后续算法 / 对偶章节可能继续使用`。

原则：

`章节阶段优先纵向读透，不要同时承担横向织网。`

## 8. 跨章节双链延迟统一审查

章节内部双链可以在本章整理时正常建立。

跨章节双链原则上等各章主体都完成后，再统一判断：

- 是否真的是依赖关系；
- 是否只是同名概念；
- 是前置关系、推广关系还是应用关系；
- 是否值得建立双向链接；
- 应链接知识点笔记、讲解版、思维导图还是碎片问答。

以下情况可以提前建立明确的跨章双链：

- 当前原文明确引用另一章节；
- 属于已经稳定确认的基础概念；
- 不建立链接会明显影响当前笔记理解。

其余关系优先作为候选记录，待全书综合后再处理。

## 9. 所有章节完成后，再进行全书综合

全书综合阶段重点研究：

- 各章节为什么按这个顺序出现；
- 哪些章节是前置基础；
- 哪些章节是方法发展；
- 哪些章节是应用展开；
- 同一个数学结构在哪些章节重复出现；
- 哪些概念发生了推广、抽象或特化；
- 哪些方法之间存在选择关系；
- 哪些章节之间应建立双链；
- 哪些知识适合抽成跨章节原子笔记。

最后形成：

`章节地图 → 前置依赖 → 概念演化 → 方法关系 → 跨章母题 → 双链网络`

## 10. 最终全局审校

长篇资料全部整理完成后，再进行一次全局检查，必要时可交给独立审校 Agent。

重点检查：

- 是否遗漏章节或教材小节；
- 不同章节 Agent 是否造成术语 / 符号不一致；
- 是否因为不同 Agent 写作导致四类笔记职责漂移；
- 是否有同一个基础概念在多个章节重复完整讲解；
- 跨章双链是否过多或牵强；
- 全书综合是否存在事后强行串联；
- 是否有值得抽成独立碎片问答 / 原子知识的跨章母题。

完整工作链：

`全书结构扫描 → 分章隔离学习 → 分章验收 → 全书综合 → 跨章双链补全 → 全局审校`
