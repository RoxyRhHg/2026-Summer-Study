# 2026 暑假学习笔记协作规范

## 适用范围

- 本文件适用于`基础知识/2026暑假学习/`及其全部子目录。
    
- 所有课程和主题统一采用四类笔记协同工作的结构：
    
    - `知识点型笔记`
        
    - `整章串联讲解笔记`
        
    - `章节思维导图笔记`
        
    - `碎片知识问答笔记`
        
    
- 教材、讲义、PPT、学习中的真实疑问、课堂重点、典型模型和后续补充，都应进入同一知识网络。
    
- 除非用户重新指定工作顺序，当前应优先完成并验收当前正在处理的章节，再继续下一章。
    
- 其他 agent 接手工作时，应把本文件视为当前项目最高优先级的本地协作规则之一，不应仅依赖历史聊天印象。
    
- 只要任务涉及`整本教材 / 较长讲义 / 完整课程 / 多章节教程 / 其他长篇学习资料`，无论是否属于“其他 Agent 接续工作”，都必须实际创建子 Agent，并触发本文的`长篇教材 / 讲义 / 课程的分章学习与子 Agent 调度`规则；仅声明“将分章处理”不算完成触发。
    

---

# 零、长篇资料子 Agent 强制门禁

> [!danger] 执行门禁
> 当任务触发本节时，主 Agent 在完成最小必要的资料结构扫描后、进入任何章节正文研究或修改前，必须实际调用子 Agent。未实际创建子 Agent，不得继续由主 Agent 单独完成章节工作。

## 1. 触发范围

满足下列任一条件即自动触发：

- 研究或整理整本教材、完整课程或较长讲义；
    
- 任务明确跨越两个及以上章节；
    
- 用户要求系统完善、补全或重构一门课程 / 一本教材的笔记；
    
- 需要持续进行分章深读、分章归纳或跨章综合。

以下任务本身不触发：

- 只回答一个明确的局部知识问题；
    
- 只修改工作流、模板或`AGENTS.md`，且不进入教材正文研究；
    
- 用户明确要求本次不得使用子 Agent。

## 2. 唯一成功判据

`已触发子 Agent`必须同时满足：

- 主 Agent 已实际调用子 Agent；
    
- 已获得可识别的子 Agent 名称、任务名或标识；
    
- 已明确该子 Agent 负责的章节或独立任务边界。

以下情况都不算触发成功：

- 只说“将使用子 Agent”；
    
- 只建立分章计划；
    
- 只采用章节隔离阅读；
    
- 主 Agent 自己完成全部章节工作后，再声称遵循了子 Agent 规则。

## 3. 强制执行顺序

`主 Agent 扫描目录与章节边界 → 创建当前章节子 Agent → 子 Agent 完成章节闭环 → 主 Agent 验收 → 再调度下一章`

- 默认按章节依赖顺序一次处理一章，不因使用子 Agent 就盲目并行。
    
- 主 Agent 负责全书地图、调度、验收和跨章候选关系记录，不代替章节子 Agent 深写正文。
    
- 章节子 Agent 负责`原文深读 → 知识点型笔记 → 讲解版 → 思维导图 → 必要碎片问答`的当前章闭环。

## 4. 失败处理

- 如果子 Agent 工具不可用、创建失败或并发槽位不足，主 Agent 必须停止进入章节正文。
    
- 主 Agent 应向用户明确说明阻塞原因；不得静默退化为单 Agent 完成长篇任务。
    
- 工具恢复或槽位释放后，应从“实际创建子 Agent”这一步继续。

## 5. 可观察性与审计

- 首次工作更新必须报告：`是否已触发 / 子 Agent 标识 / 负责章节 / 主从职责边界`。
    
- 最终交付必须再次报告实际使用的子 Agent 及其完成范围。
    
- 若任务满足触发条件，但最终无法提供子 Agent 标识，则本次流程视为未通过，不得标记为完成。

# 一、整体目标

## 1. 四类笔记各司其职

### 知识点型笔记

负责：

- 定义
    
- 定理
    
- 性质
    
- 模型
    
- 公式
    
- 成立条件
    
- 必要推导
    
- 使用方法
    
- 直接解释
    
- 易错点
    

目标是：

`完整、准确、可查、可独立阅读`

---

### 整章串联讲解笔记

负责：

- 为什么本章这样展开
    
- 为什么前一个知识点会引出后一个知识点
    
- 一个公式或模型为什么这样建立
    
- 不同知识点之间的因果关系
    
- 方法之间如何选择
    
- 本章知识如何形成统一理解
    

目标是：

`易懂、连续、有主线，但不堆砌`

---

### 章节思维导图笔记

负责：

- 快速回顾
    
- 知识定位
    
- 核心关系索引
    
- 方法入口
    
- 模型对照
    
- 易混关系
    

目标是：

`高密度、短、快、可扫读`

思维导图不是第二篇讲解笔记。

---

### 碎片知识问答笔记

负责：

- 一个具体卡点
    
- 一个容易混淆的概念
    
- 一个局部公式为什么成立
    
- 一个特殊情况
    
- 一个常见误区
    
- 一个需要单独反复复习的问题
    

目标是：

`一篇只解决一个明确问题`

---

## 2. 四类笔记不能靠重复来追求“完整”

- 如果某段定义、公式和完整推导已经在知识点型笔记中存在：
    
    - 讲解版只保留理解该知识所需的关键步骤。
        
- 如果某段内容已经在讲解版中承担连续解释：
    
    - 思维导图只保留结论、公式、对应关系和必要双链。
        
- 如果只是一个局部疑问：
    
    - 不应在知识点笔记和讲解版中反复展开；
        
    - 应优先拆成碎片知识问答笔记。
        

判断标准：

- `知识点型`打开后，应能查明“是什么、什么时候成立、怎么用”。
    
- `讲解版`连续阅读时，应能理解“为什么这样推进”。
    
- `思维导图`应该适合扫读，而不是慢慢从头阅读。
    
- `碎片问答`应该只解决一个问题。

# 二、资料与事实来源

## 1. 原始资料优先

- 数学事实优先来自：
    
    - 原始教材
        
    - 课程讲义
        
    - PPT
        
    - 论文
        
- 不以聊天回答作为数学事实的最终依据。
    
- 不应因为已有旧笔记，就默认旧笔记中的内容全部正确。
    
- 对话内容主要用于：
    
    - 理解方式
        
    - 问题意识
        
    - 学习卡点
        
    - 类比
        
    - 表达优化
        
- 数学结论仍需回到原始资料核对。

# 三、Zotero Markdown 原始资料优先

## 1. 基本原则

- 教材、课程讲义和论文内容应`尽量直接来源于 Zotero 中已经转换或导出的 Markdown 版本`。
    
- 不应优先依赖：
    
    - 聊天记录
        
    - 旧笔记
        
    - 网络二手总结
        
- 如果 Zotero 中已经存在可读的 Markdown 版本，应优先读取 Markdown，而不是重复解析 PDF。
    

---

## 2. 推荐资料优先级

原则上按以下顺序使用：

1. `Zotero 中的教材 Markdown`
    
2. `Zotero 中的讲义 / PPT Markdown`
    
3. `Zotero 条目及其附件信息`
    
4. `Zotero 原始 PDF / 原始附件`
    
5. 其他可靠原始来源
    
6. 对话内容和已有笔记
    

其中：

- 教材 Markdown 主要负责：
    
    - 章节结构
        
    - 定义
        
    - 定理
        
    - 公式
        
    - 正文例题
        
    - 完整知识边界
        
- 讲义 / PPT Markdown 主要负责：
    
    - 课堂重点
        
    - 教材之外的补充
        
    - 额外推导
        
    - 课程强调内容
        
    - 特殊例子
        
    - 课程使用的参数化或表达方式
        

---

## 3. 开始新章节前的资料检查

开始整理一个新章节前，应优先查找对应的 Zotero Markdown，并尽量从原文确定：

- 实际章节边界
    
- 小节数量
    
- 小节标题
    
- 定义
    
- 定理
    
- 公式
    
- 例题
    
- 特殊说明
    
- 讲义补充内容
    

不要预先假设某章固定有多少节。

---

## 4. 教材与讲义发生差异时

- 教材定义完整章节边界。
    
- 讲义选择性省略某个教材小节，不代表可以删除该小节。
    
- 讲义新增内容，应并入最相关的教材知识点。
    
- 如果教材与讲义：
    
    - 符号不同
        
    - 参数化不同
        
    - 推导形式不同
        
- 应先判断是否只是表示方式不同。
    
- 若存在实质差异，应核对课程实际语境后再写入笔记。
    

---

## 5. Markdown 转换异常时

如果 Zotero Markdown 中出现：

- 公式残缺
    
- 矩阵错位
    
- 图表缺失
    
- 页序错误
    
- 特殊字符乱码
    
- 章节结构明显异常
    

则：

- 不要直接把异常内容写入笔记。
    
- 应回到 Zotero 原始 PDF / 附件核对。
    

只要 Markdown 内容完整可靠，就优先使用 Markdown，避免无意义地重复解析 PDF。

---

## 6. 不得虚构资料读取情况

如果没有实际读取 Zotero Markdown，不得写：

- “已根据 Zotero 教材整理”
    
- “已阅读 Zotero 讲义”
    

必须区分：

- 已实际读取 Zotero Markdown
    
- 使用了其他等价原始来源
    
- 尚未完成 Zotero 原文复核

# 四、既有笔记参照原则

- 既有笔记主要参考：
    
    - 排版
        
    - 表达密度
        
    - Obsidian 结构
        
    - 双链方式
        
- 不默认旧笔记的知识内容正确。
    
- 用户明确表示“不满意旧笔记”时：
    
    - 不应继续以旧笔记作为内容来源。
        
    - 应把原始教材 / 讲义当成全新资料重新整理。
        
- 不应只根据文件名猜测笔记结构。
    
- 修改前先实际读取相关文件。

# 五、知识点型笔记

## 1. 基本定位

知识点型笔记是：

`定义、定理、性质、模型、公式和方法的稳定载体`

首先保证：

- 正确
    
- 完整
    
- 清楚
    
- 可查
    

---

## 2. 每个知识点至少写清

根据知识点性质，至少应覆盖：

- 研究对象 / 问题
    
- 定义
    
- 符号
    
- 变量含义
    
- 成立条件
    
- 适用范围
    
- 关键公式
    
- 关键性质
    
- 必要计算步骤
    
- 必要推导
    
- 直接解释
    
- 易错点
    

---

## 3. 内容尺度

不能只剩：

- 标题
    
- 一条公式
    
- 几个关键词
    

但也不要承担整章讲解功能。

判断标准：

> 单独打开该笔记时，读者能理解这个知识是什么、何时成立、怎样使用、最容易错在哪里。

---

## 4. 当前知识点型基准

当前可参考：

`凸优化/7 统计估计/7.1 参数分布估计.md`

主要学习：

- 信息完整度
    
- 公式密度
    
- 解释尺度
    
- 条件与结论关系
    
- 讲义补充嵌入方式
    

不要求后续章节复制其标题结构。

---

## 5. 推荐层级

- 一级标题：
    
    - 节编号 + 节名
        
    - 例如：`# 7.1 参数分布估计`
        
- 二级标题：
    
    - 教材核心板块
        
    - 主要模型
        
    - 统一总结
        
- 三级标题：
    
    - 具体公式
        
    - 特殊模型
        
    - 教材例子
        
    - 局部方法
        

---

## 6. 内容结构

主要条目尽量形成：

`对象 / 问题 → 数学表达 → 条件 → 结论 / 解释`

---

## 7. 教材例题

重要例子不能只保留结论。

至少保留：

- 关键模型
    
- 核心公式
    
- 决定凸性的步骤
    
- 最终优化形式
    

不必机械抄完整代数过程。

---

## 8. 讲义补充

- 放在对应知识点附近。
    
- 明确标记为：
    
    - `讲义补充`
        
    - `课程讲义补充`
        
- 不另造与教材冲突的一级章节编号。
    

---

## 9. 文末规则

默认不添加：

- `关联`
    
- `章节串联讲解`
    
- `资料来源`
    
- `参考资料`
    

除非用户明确要求。

# 六、整章串联讲解笔记

## 1. 基本定位

负责回答：

- 本章为什么这样展开？
    
- 前一部分为什么引出后一部分？
    
- 不同模型为什么会出现？
    
- 同一个优化结构在不同统计问题中如何复用？
    

---

## 2. 核心原则

讲解版追求：

`完整但不堆砌`

不是：

`越长越好`

---

## 3. 同一个原理只完整推一次

例如：

多个噪声模型都来自：

$\phi(r)=-\log p(r)$

则：

- 第一次完整推导：
    
    - IID
        
    - 联合似然
        
    - 取对数
        
    - 负对数似然
        
    - 得到 penalty
        
- 后面的：
    
    - Gaussian
        
    - Laplace
        
    - Uniform
        
- 重点写差异，不再逐个完整重复联合似然推导。
    

---

## 4. 相似模型优先讲差异

后续模型重点回答：

- 新增了什么？
    
- 与前面相比哪里改变？
    
- 为什么需要这个模型？
    
- 它带来了什么新的凸结构？
    

---

## 5. 每个教材一级小节围绕一个核心问题

推荐结构：

- 核心问题
    
- 统一模型 / 母式
    
- 关键推导
    
- 模型分支
    
- 必要补充
    
- 极短过渡
    

避免：

大量同级：

- 为什么……
    
- 再来看……
    
- 从哪里来……
    
- 为什么还要……
    
- 这次又为什么……
    

---

## 6. 标题不能过碎

局部“为什么”如果只需要一两段：

- 直接放正文解释。
    
- 不要全部做成三级或四级标题。
    

标题只承担真正的知识转折。

---

## 7. 推导只保留关键步骤

重点保留：

- 为什么这样变形
    
- 决定凸性的步骤
    
- 为什么换变量
    
- 为什么某个约束是凸的
    
- 为什么某个模型自然出现
    

可以删除：

- 纯代数重复
    
- 已经在知识点型笔记中完整存在的计算
    

必要时通过双链承接。

---

## 8. 相似内容优先用表格

适合表格的典型内容：

- Gaussian / Laplace / Uniform
    
- D / E / A optimal
    
- ML / MAP
    
- Chebyshev / Chernoff
    
- 参数估计 / 非参数估计
    

表格用于：

`比较`

不用于塞长篇推导。

---

## 9. 禁止重复总结

避免出现：

- 正文讲一遍
    
- 节末总结完整讲一遍
    
- 最短记忆链再讲一遍
    
- 全章总结再讲一遍
    

节末最多保留：

1—3 条真正用于承接下一节的结论。

全章最后统一收束一次。

---

## 10. 重复判断标准

如果删掉某段以后：

- 结论没有丢失
    
- 理解没有断裂
    
- 前后仍然顺畅
    

则该段大概率属于重复内容，应删除或合并。

---

## 11. 当前讲解版基准

当前参考：

`凸优化/7 统计估计/7 统计估计（讲解版）.md`

该版本已经从早期：

- 内容堆砌
    
- 同一逻辑反复出现
    
- 标题过碎
    
- 相似模型重复推导
    

调整为：

- 每节一个核心问题
    
- 统一原理先出现
    
- 模型只讲新增点
    
- 减少重复总结
    
- 主干与补充分层
    

后续讲解版应复用这种方法，而不是复制其章节标题。

# 七、章节思维导图笔记

## 1. 基本定位

思维导图只负责：

- 快速回顾
    
- 知识定位
    
- 关系索引
    

不承担：

- 长篇动机
    
- 连续讲解
    
- 完整推导
    

---

## 2. 思维导图不是第二篇讲解版

如果某段需要连续说明：

“为什么 A 导致 B，为什么又产生 C”

应放到：

`整章串联讲解笔记`

思维导图只保留：

`A → B → C`

及必要公式。

---

## 3. 无固定跨章节模板

不同章节可以按不同方式组织：

- 对象 → 性质
    
- 条件 → 结论
    
- 问题 → 方法
    
- 方程类型 → 解法
    
- 模型 → 准则
    
- 题型 → 入口
    
- 知识依赖
    
- 典型计算方法
    

不能因为一篇优秀导图使用某结构，就复制到所有章节。

---

## 4. 参考成熟考研导图

当前重点参考：

`E:/Obsdian/Script/考研/数一/2 线代/1 行列式/1-0 行列式思维导图.md`

以及其他：

- 线代思维导图
    
- 高数思维导图
    
- 概率论思维导图
    

学习的是：

- 为什么这样分类
    
- 信息怎么压缩
    
- 标题怎么命名
    
- 公式怎么嵌入
    
- 怎样快速扫读
    

不是复制：

- 标题数量
    
- 缩进层数
    
- 版式外观
    

---

## 5. 标题必须短

优先使用：

- 概念名
    
- 方法名
    
- 性质名
    
- 模型名
    
- 题型名
    

例如：

- `最大似然估计`
    
- `Gaussian 协方差估计`
    
- `鲁棒检测`
    
- `Chernoff 界`
    
- `D/E/A-optimal`
    

避免：

- “先抓住本章真正的主线”
    
- “为什么这个问题最后会变成……”
    
- “真正应该注意的是……”
    
- “一句话理解……”
    

这些属于讲解版语言。

---

## 6. 信息密度来源

思维导图的高密度来自：

- 核心定义
    
- 核心公式
    
- 成立条件
    
- 重要性质
    
- 方法选择
    
- 模型对应
    
- 特殊情况
    
- 易混点
    
- 双链
    

不是来自：

- 长段落
    
- 长篇动机
    
- 多次重复总结
    

---

## 7. 一条列表一个复习单元

尽量做到：

一条列表读完，就能得到一个完整结论。

---

## 8. 公式排版

思维导图中的公式：

默认优先使用：

`$...$`

即使公式重要，也尽量保持行内。

只有以下情况使用：

`$$...$$`

- 长矩阵
    
- 分段函数
    
- 复杂多行结构
    
- 确有强调或排版需要
    

目的：

- 减少纵向长度
    
- 提高快速浏览效率
    

---

## 9. 横向联系必须短

例如：

- `Gaussian 噪声 ↔ 最小二乘`
    
- `Laplace 噪声 ↔ $\ell_1$`
    
- `MAP ↔ 正则化`
    
- `分布不确定集 ↔ 鲁棒检测`
    
- `判决区域 ↔ 概率界`
    

不要把这些关系扩成一整节长篇说明。

- 但不强制决定：
    
    - 导图最高层组织结构
        

导图可以重新按更适合复习的知识块组织。

# 八、碎片知识问答笔记

> [!important] 本节规则仅用于“碎片问答原子笔记”
> 以下经验专门用于处理学习过程中临时出现的具体卡点、追问、辨析和局部推导，不用于整章讲解版、知识点型笔记或思维导图。目标是把一次高质量问答沉淀成可独立复习的原子笔记。

## 1. 一篇只解决一个问题

标题直接写问题。

例如：

- `似然函数中什么是变量，什么是已观测量`
    
- `Logistic 损失为什么是凸函数`
    
- `Bernoulli 负对数似然为什么等于交叉熵`
    
- `为什么在线性化模型中加入二次惩罚`
    
- `为什么不用更高次惩罚代替二次惩罚`
    
一篇原子笔记只解决一个核心疑问；如果回答过程中自然冒出另一个可以独立成立的问题，应优先拆成新的原子笔记，而不是继续无限扩张当前笔记。

---

## 2. 内容结构

默认按下面的理解路径组织，但不要机械套成固定标题模板：

- `最小必要上下文`：只交代理解当前问题必须知道的前提。
    
- `明确问题`：先说清“到底哪里让人困惑”。
    
- `问题意识`：解释为什么会产生这个设计、公式或定义，而不是直接丢结论。
    
- `直觉解释`：先用自然语言说明它在“做什么”。
    
- `关键推导`：把真正决定理解的数学步骤逐行写清。
    
- `为什么不是别的做法`：若用户卡点来自“为什么偏偏这样”，主动比较最自然的替代方案。
    
- `最终结论`：用一句或少数几句收束真正应该记住的东西。
    
- `必要条件 / 边界`：说明结论什么时候成立，避免把特殊情形记成普遍规律。
    
- `常见误区`：只写与当前问题高度相关的误解。
    
重点不是标题齐全，而是保证阅读路径遵循：

`先知道为什么问 → 再知道它在干什么 → 再看公式为什么成立 → 最后形成可复述的结论`

---

## 3. 回答时优先处理“为什么”，再处理“怎么算”

碎片问答常常不是因为用户不会代数，而是因为不知道：

- 为什么会想到这个构造；
    
- 为什么偏偏选择这种形式；
    
- 这个系数从哪里来；
    
- 为什么不用看起来更直接的替代方案；
    
- 这个公式和前面知识有什么关系。
    
因此不要一上来就只做公式推导。

例如二次惩罚问题，不能只写：

$$\nabla f(y)+L(x-y)=0\Rightarrow x=y-\frac1L\nabla f(y).$$

还应先解释：

- 单独线性化为什么会无界下降；
    
- 为什么需要限制离当前点的距离；
    
- 为什么二次是最低阶且与 Taylor 误差匹配的选择；
    
- 为什么$L$与 Lipschitz 梯度 / 曲率上界有关。
    
---

## 4. 先直觉，后公式，再回到更深的数学来源

碎片问答的推荐解释顺序是：

`一句直觉 → 一个最简单例子 → 一般公式 → 更深的理论来源`

例如：

- 先说“梯度告诉你往哪走，二次项告诉你别走过头”；
    
- 再用一维$-ct+\frac L2t^2$解释为什么存在有限最小值；
    
- 再推到向量形式；
    
- 最后连接 Descent Lemma、Hessian 上界或 Lipschitz 梯度。
    
这种顺序比“定义 → 定理 → 证明”更适合真实学习卡点。

---

## 5. 推导要逐步，但只展开真正决定理解的步骤

遇到关键公式时，不要使用：

- “显然”；
    
- “容易得到”；
    
- “直接可知”。
    
如果某一步正是用户困惑来源，就应拆开。

但也不要把所有初等代数都展开到失去主线。

判断标准：

> 省略这一步后，用户是否仍能解释“为什么从上一式能到下一式”？

如果不能，就应写出来。

---

## 6. 主动回答“为什么不是另一个看起来也合理的方案”

碎片问答中，这类对比往往比单独给结论更能消除卡点。

典型问题包括：

- 为什么是平方惩罚，不是一次、三次、四次？
    
- 为什么是最大化凹函数 / 最小化凸函数？
    
- 为什么 Logistic 要对 log-odds 线性，而不是概率直接线性？
    
- 为什么同样是$L_1$，作用在残差和作用在参数上含义不同？
    
比较时应说明真正的判据，而不是只说“因为这样更常用”。

---

## 7. 用最小真实例子把抽象公式落地

当用户对抽象符号没有形成感觉时，优先构造一个最小、可计算的真实场景，例如：

- 电子秤重复测量 → Gaussian 噪声 → 最小二乘；
    
- 欧姆定律$U_i=I_iR+v_i$ → $a_i\neq1$的线性观测；
    
- 疾病二分类 → Bernoulli + Logistic；
    
- 图像去模糊 → 数据保真项 + 先验正则项。
    
例子的作用是解释符号角色和因果关系，不要为了“真实”加入大量无关背景。

---

## 8. 符号角色必须明确

碎片问答特别容易因为字母过多而失去理解。

遇到统计、优化、逆问题时，应明确区分：

- `已知量`；
    
- `观测量`；
    
- `优化变量 / 待估参数`；
    
- `随机变量`；
    
- `残差 / 噪声`；
    
- `当前迭代点`；
    
- `局部模型中的候选点`。
    
尤其像$x,y,a_i,u_i,p_i,z_i$连续出现时，不要默认读者能一直记住角色。

---

## 9. 一次回答尽量形成一条连续主线

避免把回答写成大量彼此平行的小标题和重复总结。

一篇碎片问答应能压缩成一条因果链，例如：

`线性化无界 → 需要稳定项 → 二次项压住线性下降 → Lipschitz 梯度又恰好给出二次误差上界 → 最小化后得到步长$1/L$`

或者：

`Bernoulli 模型 → 似然 → 对数似然 → 负号 → 交叉熵`

如果读完后不能用一条链复述，说明内容可能仍然太散。

---

## 10. 结尾只保留真正值得记住的结论

碎片问答可以在结尾留一个极短的`核心记忆`，但不要出现：

- 正文总结一次；
    
- 节末总结一次；
    
- “最短记忆链”再总结一次；
    
- 最后再完整总结一次。
    
通常只保留：

- 一句直觉；
    
- 一条关键公式；
    
- 一条与前后知识的连接。
    
即可。

---

## 11. 原子笔记不是聊天记录搬运

把对话沉淀成本地笔记时，应重新组织，而不是原样复制聊天回答。

需要：

- 去掉对话式寒暄和重复承接；
    
- 合并重复解释；
    
- 保留用户真正卡住的“为什么”；
    
- 保留关键推导和反例；
    
- 添加必要的[[双链]]；
    
- 按 Obsidian Markdown 规范调整公式与术语格式。
    
目标是：

`聊天时足够掰碎，落盘后足够清晰。`

---

## 12. 不复制整节笔记

碎片问答不是：

`把知识点型笔记再抄一遍`

只解决当前问题。

如果为了回答一个问题不得不连续覆盖整章多个知识点，应考虑：

- 把核心卡点留在当前原子笔记；
    
- 其余内容通过[[双链]]连接到知识点型或讲解版；
    
- 或拆成多个独立原子笔记。
    
---

## 13. 双链

在对应知识点附近加入问答双链。

不要只在文末集中列一个问答清单。

碎片问答内部也应在真正发生知识连接的位置链接，例如：

- 二次惩罚 → [[Lipschitz 条件]]；
    
- 局部二次模型 → [[梯度下降]]；
    
- prox → [[Proximal Gradient]]；
    
- 近端梯度加速 → [[0 FISTA（讲解版）]]。

双链的目的不是增加链接数量，而是把“这个卡点属于哪条知识链”固定下来。

---

$$

# 长篇教材 / 讲义 / 课程的分章学习与子 Agent 调度（高优先级触发规则）

> [!important] 触发条件
> 只要当前任务的研究对象是整本教材、较长讲义、完整课程、多章节教程或其他跨多个章节的长篇学习资料，本节就自动生效。该规则适用于任何 Agent，不以“接续工作”“是否使用子 Agent”或“用户是否再次提醒”为前提。



本节专门用于处理：

- 整本教材
    
- 较长课程讲义
    
- 完整课程
    
- 多章节论文式教程
    
- 其他需要跨多个章节持续学习和归纳的长篇资料
    

核心原则是：

`先建立全书地图，但不提前概括全书 → 每次只聚焦一个章节深读 → 所有章节分别完成后，再统一研究跨章联系与双链`

第一次学习主要解决：

`每一章到底讲了什么`

第二次全书综合才解决：

`这些章节为什么会组成一本书 / 一门课，以及它们之间怎样连接`

### 1. 第一阶段只扫描全书结构，不急着做全书总结

开始处理整本教材或完整课程时，应先读取：

- 目录
    
- 前言 / syllabus / 课程大纲
    
- 章节标题
    
- 小节标题
    
- 教材与讲义之间的大致章节对应关系
    

这一阶段的目标只是确定：

- 全书有哪些部分
    
- 有哪些章节
    
- 每章大致边界
    
- 哪些讲义 / PPT 对应哪些章节
    
- 后续应按什么顺序逐章处理
    

不得因为已经看过目录，就直接：

- 一口气概括所有章节内容
    
- 提前总结整本书的核心思想
    
- 预先替每章规定“真正主线”
    
- 根据目录标题脑补章节内容
    

原则：

`第一次全书阅读主要建索引，不提前建立最终结论。`

### 2. 章节研究采用“内容上下文隔离”

研究某一章时，知识内容上下文原则上只围绕当前章节展开。

当前章节 Agent 主要读取：

- 当前章节教材 Markdown / 原文
    
- 当前章节对应讲义 / PPT Markdown
    
- 当前章节必要附件
    
- `AGENTS.md` 中的协作规范
    
- 全书目录中用于定位当前章的最小结构信息
    

默认不要同时把以下内容大规模带入当前章上下文：

- 其他章节完整正文
    
- 其他章节完整笔记
    
- 后续章节结论
    
- 之前 Agent 对整本书的主观总括
    

目的不是人为切断知识联系，而是避免：

- 当前章节细节被整书内容稀释
    
- 尚未细读就被已有概括框住
    
- 因为提前知道后文而反向改写当前章的原始展开
    
- 无法判断一个知识点在当前章究竟讲到了什么程度
    

### 3. 允许“最小必要回查”，但禁止无目的扩展上下文

章节隔离不等于禁止查阅前置知识。

如果当前原文明确依赖其他章节中的：

- 定义
    
- 定理
    
- 公式
    
- 符号约定
    

且不回查就无法准确理解当前内容，可以定点回查必要部分。

例如：

当前章使用前文的`Lipschitz gradient`，可以只回查该定义及理解当前推导所需的最小内容，而不是重新把前一整章读入当前上下文。

原则：

`需要什么，就回查什么；不要因为存在跨章引用，就把其他章节整体带入。`

### 4. 长篇学习必须使用“总控 Agent → 章节 Agent → 全书综合 Agent”结构

对于多章节长篇资料，必须实际创建子 Agent 进行上下文隔离。仅分章处理或声明计划使用子 Agent，不算满足本规则；具体成功判据和失败处理以前文`零、长篇资料子 Agent 强制门禁`为准。

#### 总控 Agent

负责：

- 读取本`AGENTS.md`
    
- 扫描全书目录与资料结构
    
- 确认章节边界
    
- 建立章节任务清单
    
- 安排章节处理顺序
    
- 记录章节完成状态
    
- 保存待验证的跨章关系候选
    

在所有章节深读完成前，总控 Agent 原则上不负责：

- 提前写最终全书总结
    
- 给所有章节预设统一解释框架
    
- 仅根据目录替各章定义核心思想
    
- 提前构造完整跨章知识网络
    

即：

`总控 Agent 先负责调度，不抢章节 Agent 的内容研究工作。`

#### 章节 Agent

每个章节 Agent 必须使用相对独立的上下文。

章节 Agent 负责当前章的闭环：

`原文深读 → 章节结构确认 → 知识点型笔记 → 整章讲解版 → 思维导图 → 必要碎片问答 / 卡点记录`

章节 Agent 应优先保证：

- 当前章事实完整
    
- 当前章内部逻辑清楚
    
- 当前章教材与讲义对应准确
    
- 当前章四类笔记各司其职
    

章节 Agent 不应顺手承担整本书的知识网络设计。

#### 全书综合 Agent

只有在所有章节都已经分别完成并验收之后，再进入全书综合阶段。

全书综合 Agent 优先读取：

- 全书目录
    
- 各章思维导图 / 高密度章节摘要
    
- 各章关键结构
    
- 各章节留下的跨章候选关系
    

先基于这些压缩后的章节结果建立全书关系，再对不确定关系定点回查原教材。

不建议一开始重新把整本原教材全部塞进一个超大上下文后再总结。

### 5. 章节默认顺序处理，不因使用子 Agent 就盲目并行

`上下文隔离`不等于`所有章节同时并行`。

如果教材存在明显前后依赖，默认按照教材顺序执行：

`Ch1 Agent 完成并验收 → Ch2 Agent → Ch3 Agent → ...`

这样可以：

- 保留课程自然学习顺序
    
- 及时吸收前一章验收中得到的方法经验
    
- 避免多个 Agent 同时对同一基础概念产生不同理解
    

只有在章节明显彼此独立时，才适合并行处理，例如：

- 相互独立的应用专题
    
- 附录型专题
    
- 无前置依赖的案例章节
    

原则：

`章节内容要隔离，任务调度默认仍按依赖顺序进行。`

### 6. 每章先纵向读透，再延迟处理系统性跨章联系

当前章节尚未完成时，优先解决：

- 本章研究什么
    
- 为什么这样展开
    
- 定义、定理、公式和模型是什么
    
- 本章内部知识如何连接
    

对明显的跨章联系，可以先记录为：

- `跨章候选关系`
    
- `待全书串联`
    
- `待双链审查`
    

例如：

- `proximal gradient ← 依赖 Lipschitz gradient`
    
- `MAP ↔ 正则化`
    
- `KKT → 后续算法 / 对偶章节可能继续使用`
    

此时不必立即展开为完整跨章解释。

原则：

`章节阶段优先纵向读透，不要同时承担横向织网。`

### 7. 跨章节双链默认延迟到全书综合阶段统一审查

章节内部双链可以在本章整理时正常建立。

跨章节双链则原则上等各章主体都完成后，再统一判断：

- 是否真的是依赖关系
    
- 是否只是同名概念
    
- 是前置关系、推广关系还是应用关系
    
- 是否值得建立双向链接
    
- 应链接知识点笔记、讲解版、思维导图还是碎片问答
    

以下情况可以提前建立明确的跨章双链：

- 当前原文明确引用另一章节
    
- 属于已经稳定确认的基础概念
    
- 不建立链接会明显影响当前笔记理解
    

其余关系优先作为候选记录，待全书综合后再处理。

### 8. 所有章节完成后，再第一次真正进行全书综合

全书综合阶段重点研究：

- 各章节为什么按这个顺序出现
    
- 哪些章节是前置基础
    
- 哪些章节是方法发展
    
- 哪些章节是应用展开
    
- 同一个数学结构在哪些章节重复出现
    
- 哪些概念发生了推广、抽象或特化
    
- 哪些方法之间存在选择关系
    
- 哪些章节之间应建立双链
    
- 哪些知识适合抽成跨章节原子笔记
    

最后形成：

`章节地图 → 前置依赖 → 概念演化 → 方法关系 → 跨章母题 → 双链网络`

而不是在第一遍读目录时提前决定这些关系。

### 9. 全书综合后进行一次全局审校

长篇资料全部整理完成后，建议再进行一次全局检查，必要时可交给独立审校 Agent。

重点检查：

- 是否遗漏章节或教材小节
    
- 不同章节 Agent 是否造成术语 / 符号不一致
    
- 是否因为不同 Agent 写作导致四类笔记职责漂移
    
- 是否有同一个基础概念在多个章节重复完整讲解
    
- 跨章双链是否过多或牵强
    
- 全书综合是否存在事后强行串联
    
- 是否有值得抽成独立碎片问答 / 原子知识的跨章母题
    

完整推荐工作链：

`全书结构扫描 → 分章隔离学习 → 分章验收 → 全书综合 → 跨章双链补全 → 全局审校`

# 十七、其他 Agent 接续工作的推荐流程

其他 agent 接手时，开始修改前至少应阅读：

1. 当前目录的`AGENTS.md`
    
2. 当前章节知识点笔记
    
3. 当前章节思维导图
    
4. 当前章节整章讲解版
    
5. 与本次任务直接相关的碎片问答
    
6. 对应 Zotero 教材 / 讲义 Markdown
    

---

## 推荐顺序

处理新章节时：

### 第一步：确认原始资料

优先找到：

- Zotero 教材 Markdown
    
- Zotero 讲义 Markdown
    

确认：

- 章节结构
    
- 小节
    
- 公式
    
- 内容边界
    

---

### 第二步：确定章节自然组织方式

不要套模板。

判断本章更适合：

- 对象—性质
    
- 问题—方法
    
- 条件—结论
    
- 模型—选择
    
- 方程类型—解法
    
- 知识依赖
    
- 题型入口
    

---

### 第三步：先完成知识点型笔记

目的：

`保证事实完整`

---

### 第四步：完成整章讲解版

目的：

`建立理解路径`

先统一原理，再展开真正不同的模型。

---

### 第五步：最后压缩思维导图

目的：

`快速复习`

不要反过来先做导图再推教材内容，否则容易遗漏。

---

### 第六步：拆碎片问答

学习中遇到：

- 卡点
    
- 辨析
    
- 局部推导
    

单独建笔记。

---

# 十八、修改与检查流程

完成修改后至少检查以下内容。

---

## 0. 子 Agent 调度

当任务属于长篇资料时，检查：

- 是否在进入章节正文前实际创建了子 Agent。
    
- 是否记录了子 Agent 名称、任务名或标识。
    
- 是否明确了主 Agent 与章节 Agent 的职责边界。
    
- 是否按章节依赖顺序推进，而不是盲目并行。
    
- 子 Agent 创建失败时，是否停止正文工作并明确报告，而不是静默改为单 Agent 完成。
    
- 最终交付是否再次报告了子 Agent 的实际完成范围。

若任务满足触发条件，但以上任一关键项缺失，则不得将任务标记为完成。

---

## 1. 原始资料

- 是否实际读取了 Zotero 教材 / 讲义 Markdown。
    
- 是否存在可用 Markdown 却只依赖旧笔记。
    
- 是否误把讲义省略内容当成教材不存在。
    
- 是否存在公式乱码而未回原 PDF 核对。
    

---

## 2. 四类笔记职责

检查是否出现：

- 知识点型笔记写成讲解稿
    
- 讲解版复制知识点全文
    
- 思维导图写成第二篇讲解版
    
- 局部问题没有拆成碎片问答
    

---

## 3. 知识点型笔记

检查：

- 是否完整
    
- 是否过空
    
- 是否过度讲解
    
- 条件是否写全
    
- 公式后是否有必要解释
    
- 重要例子是否保留核心模型
    

---

## 4. 整章讲解版

重点检查：

- 是否同一内容正文讲过，节末又讲，全章又讲。
    
- 同一母式是否被多个模型重复完整推导。
    
- 是否可以先统一模型再比较差异。
    
- 是否有适合改成表格的相似模型。
    
- 标题是否过碎。
    
- 是否大量使用“为什么……”“再来看……”作为同级标题。
    
- 是否看得出：
    
    - 核心问题
        
    - 关键推导
        
    - 模型分支
        
    - 必要补充
        
- 是否真正做到：  
    `完整但不堆砌`
    

---

## 5. 思维导图

重点检查：

- 是否误写成讲解版。
    
- 标题是否过长。
    
- 是否使用大量讲解型标题。
    
- 是否存在本可用行内公式却大量使用行间公式。
    
- 是否有长段落。
    
- 是否能快速扫读。
    
- 是否保留：
    
    - 定义
        
    - 公式
        
    - 条件
        
    - 性质
        
    - 方法
        
    - 易混点
        
- 是否因为过度压缩退化成普通目录。
    
- 是否机械套用了其他章节架构。
    

---

## 6. 双链

检查：

- 是否放在真正相关位置。
    
- 是否只在文末堆关联。
    
- 思维导图、讲解版、知识点型、碎片问答之间是否形成自然网络。
    

---

## 7. 格式

检查：

- YAML 是否完整。
    
- `created`是否被误改。
    
- `updated`是否更新。
    
- 是否有`\boxed`。
    
- 行间公式是否为单行。
    
- 表格列数是否一致。
    
- 表格中是否存在裸竖线。
    
- 是否错误使用粗体术语。
    
- 子标题下是否机械使用有序列表。
    

---

# 十九、用户反馈优先原则

- 用户明确认可的写法，应及时同步进`AGENTS.md`。
    
- 用户明确否定的写法，不应因为更换 agent 再次出现。
    
- 当前已经明确否定的倾向包括：
    
    - 思维导图写成长篇讲解
        
    - 思维导图套用固定模板
        
    - 思维导图大量行间公式导致过长
        
    - 思维导图使用拖沓长标题
        
    - 讲解版内容虽然必要但无层级堆砌
        
    - 同一原理多次完整推导
        
    - 正文、节末、全章重复总结
        

其他 agent 接续时，应优先继承这些已验证经验，而不是重新试错。

---

# 二十、最终工作原则

整个项目最重要的不是让所有文件“长得一样”，而是让四类笔记共同组成一个稳定知识系统：

- `知识点型`负责准确和完整；
    
- `讲解版`负责理解和串联；
    
- `思维导图`负责压缩和复习；
    
- `碎片问答`负责解决真实卡点。
    

资料层面：

`尽量回到 Zotero 中的教材 / 讲义 Markdown 原文`

组织层面：

`根据章节本身决定架构，而不是套模板`

表达层面：

`完整，但不重复；易懂，但不堆砌；高密度，但仍然清晰。`
