# 凸优化笔记执行门禁

本目录及全部子目录同时遵守上级`基础知识/2026暑假学习/AGENTS.md`。本文件只前置最容易漏掉的长篇资料调度规则；若与上级文件存在差异，采用要求更严格且不违反用户当前指令的规则。

## 长篇任务必须实际创建子 Agent

> [!danger] 不可跳过
> 当任务涉及整本《凸优化》教材、完整凸优化课程、两个及以上章节，或用户要求系统完善凸优化笔记时，主 Agent 完成最小目录扫描后，必须在研究或修改章节正文前实际创建子 Agent。

`触发成功`必须同时满足：

- 已实际调用子 Agent；
    
- 已获得子 Agent 名称、任务名或标识；
    
- 已明确该子 Agent 负责的章节或独立任务边界；
    
- 首次工作更新已向用户报告上述信息。

只建立分章计划、只声明“将使用子 Agent”或由主 Agent 自己分章完成，都不算触发成功。

## 固定工作顺序

`主 Agent 扫描全书结构 → 创建当前章节子 Agent → 章节 Agent 完成闭环 → 主 Agent 验收 → 再调度下一章`

- 默认按教材依赖顺序逐章处理，不盲目并行。
    
- 主 Agent 负责目录、调度、验收和跨章候选关系。
    
- 章节 Agent 负责`原文深读 → 知识点型笔记 → 整章讲解版 → 思维导图 → 必要碎片问答`。
    
- 第七章若被用户指定为基准或要求不改，只能只读参照，不得把修改任务交给子 Agent。

## 无法创建时

- 若子 Agent 工具不可用、创建失败或并发槽位不足，必须停止章节正文工作并明确报告。
    
- 不得静默退化为主 Agent 单独完成。
    
- 最终交付必须报告实际使用的子 Agent 及其完成范围；无法提供子 Agent 标识时，不得把触发型任务标记为完成。

## 不触发的任务

- 只回答一个局部知识问题；
    
- 只审查或修改工作流、模板、`AGENTS.md`，且不进入教材正文；
    
- 用户明确要求本次不得使用子 Agent。
